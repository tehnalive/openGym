# Локальная проверка и развёртывание

Статус: код прототипа. Реальный Telegram требует HTTPS, собственного бота и серверного токена. Эта инструкция не означает выполненное публичное развёртывание.

## Без Docker — локальный предпросмотр

Из корня проекта:

```powershell
node scripts/dev.mjs
```

Открыть http://localhost:5174. Скрипт запускает штатный API на 3000 и Vite на 5174, хранит отдельные тестовые данные в `.cache/telegram-local-preview` и включает гостевой режим только для локального предпросмотра. Он игнорирует корневой `.env`, очищает Telegram-переменные для API и не запускает процесс бота или запросы к Bot API. Публичный сервер и его данные не затрагиваются.

Чтобы повторно открыть приветственный онбординг без сброса локальных данных, использовать `http://localhost:5174/?firstRunPreview=1#/home`. Этот dev-параметр только показывает экран; авторизацию не подменяет. Онбординг позволяет выбрать одну из трёх готовых программ, создать пустую тренировку с переходом в редактор или отложить настройку. Выбор программы или создание тренировки сохраняет изменения в тестовом профиле.

Реальный Telegram Mini App нельзя проверить открытием `localhost`: Telegram требует HTTPS и серверную проверку подписанного `initData`. Локальный preview проверяет интерфейс и обычный гостевой сценарий; он не подтверждает реальный вход в Telegram.

Зависимости перед первым запуском:

```powershell
npm --prefix api ci --ignore-scripts --omit=optional
npm --prefix frontend ci --ignore-scripts
```

## Docker

Скопировать `.env.telegram.example` в `.env`. Затем настроить `APP_HOST`, `APP_ORIGIN` и значения Telegram. Токен хранить только в `.env`/секретах сервера; не публиковать и не передавать как frontend-переменную.

Сборка и локальный запуск:

```sh
docker compose -f compose.telegram.yml up -d --build api web
```

Для сервера с доменом и Caddy (порты 80/443 должны быть свободны и доступны):

```sh
docker compose -f compose.telegram.yml --profile https --profile telegram up -d --build
```

Если HTTPS уже обслуживает другой reverse proxy, профиль `https` не включать; направить его на `127.0.0.1:8080`. Telegram-токен получают у собственного бота; подключение и внешние действия выполняются отдельно. Бот отвечает только на команды разрешённых пользователей. При существующем webhook он останавливается, не изменяя его.

Для домена на Cloudflare: DNS направить на сервер. Не заменять существующий сайт; выделить поддомен, например `gym.<ваш-домен>`. Использовать HTTPS до origin (Full/Strict). Не включать cache-everything для `/api/*` и персональных данных. Не ставить Cloudflare Access перед Mini App без отдельной проверки входа внутри Telegram.

## Приватный пилот

В `.env` указать два numeric Telegram ID в `TELEGRAM_ALLOWED_IDS`, `INVITE_ONLY=1`, `ALLOW_GUEST=0`. Пустые токен или ID не заменять тестовым обходом подписи. Первый администратор автоматически не назначается; это отдельная настройка после подтверждения аккаунта.

Для первой версии есть команда бота `/start` с кнопкой Mini App. Настройку основной Mini App/Menu Button в BotFather можно выполнить после получения рабочего HTTPS URL. Полный вход и уведомления проверить на двух Android.

## Резервные копии

Данные хранятся в `data`, не в контейнере. Перед обновлением остановить API, сохранить эту папку и `.env` в защищённую копию, затем запустить API. Копия содержит ключ сессий и личные записи. Восстановление сначала проверить на отдельной установке. JSON-экспорт профиля полезен дополнительно и не заменяет копию всего сервиса.

## Граница первой версии

Авторизация, открытие из бота и дневник входят в прототип. Telegram-напоминания, сообщения с итогами и точный тоннаж по мышцам идут следующими задачами; web push upstream не объявляется Telegram-сообщением.

Загрузка личных фото/видео в этом пилоте выключена (`MEDIA_UPLOADS=0`): её фоновая синхронизация upstream требует дополнительной защиты при смене владельца общей browser-сессии. Встроенные изображения упражнений сохраняются. AI coach также выключен; для первой проверки дневника он не требуется.
