# Telegram launcher — TG04

Отдельный процесс на **Node.js 22+**, без npm-зависимостей. При приватной команде `/start` (включая deep-link аргумент) или `/app` отвечает краткой инструкцией и кнопкой Telegram `web_app` «Открыть дневник». Группы, каналы, редактирования, другие сообщения и неразрешенные пользователи игнорируются. Команды вида `/app@botname` не обрабатываются: в приватном чате используйте `/app`.

## Переменные окружения

| Переменная | Контракт |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Обязательный серверный секрет BotFather; формат `положительный_ID:секрет` (20–200 символов `A-Za-z0-9_-`). Не размещать в Mini App, Git, Docker build args или образе. Передавать процессу при запуске. |
| `TELEGRAM_MINI_APP_URL` | Обязательный абсолютный **HTTPS** URL опубликованного Mini App, без user/password. HTTP не разрешен даже для localhost. Не размещать секреты в URL. |
| `TELEGRAM_ALLOWED_IDS` | Необязательный список положительных безопасных целых Telegram user ID через запятую; пробелы вокруг элементов допускаются. Например `12345,67890`. Если переменная отсутствует, доступ открыт всем; если задана пустой или неверно — процесс останавливается. Для личного пилота задайте ID обоих участников. |

Allowlist ограничивает только кнопку в этом боте. Доступ к самому приложению и API должен отдельно проверять сервер по Telegram auth; отправка кнопки не является авторизацией API. Это должен быть тот же бот, чьим токеном backend проверяет `initData`.

## Запуск

Из корня репозитория с уже переданными переменными окружения:

```text
node integration/telegram-bot.mjs
```

В Docker бот «Жимолости» запускается отдельным сервисом `bot` в `compose.telegram.yml`; секрет передаётся во время запуска. Процесс требует исходящего HTTPS к `api.telegram.org`; входящий порт для бота не нужен. Mini App должен быть доступен телефону пользователя по HTTPS.

До запуска Mini App должен быть настроен в BotFather. `configure-telegram-bot.mjs` читает секреты из локального `.env`, проверяет, что токен принадлежит `@Gym_statsbot`, затем задаёт имя «Жимолость», аватар, описание, About, команды и стандартную кнопку меню; после этого сверяет имя и текстовые настройки через Bot API. Запускайте его только по явному запросу на изменение настроек. Отдельную картинку поля Description можно добавить в BotFather через **Edit Description Picture**. Лаунчер не вызывает `setWebhook` или `deleteWebhook`. Вначале выполняется только `getWebhookInfo`: если webhook уже есть, процесс останавливается с объяснением. Удаление webhook — отдельное явное действие администратора. Запускайте только **один** polling-процесс на токен. Конфликт Telegram 409 или ошибка авторизации 401 останавливают процесс.

## Поведение и ограничения

- Этот процесс использует long polling `getUpdates` с timeout 30 секунд; сетевой лимит запроса — 40 секунд. Сам launcher не рассылает автоматические сообщения: его `sendMessage` здесь вызывается только в ответ на `/start` или `/app`.
- API может отдельно отправить сообщение о новой тренировке и недельный обзор, только если владелец Telegram-профиля включил их в настройках Mini App. Telegram ID берётся из серверной учётной записи после проверки initData; chat ID от клиента не принимается. Пользователь должен открыть чат с ботом и нажать Start.
- Сообщение о тренировке отправляется при синхронизации новой записи, если её завершение не старше 48 часов; один sync с несколькими новыми тренировками даёт один обзор последней. Недельный обзор за прошлый понедельник–воскресенье отправляется по понедельникам после 09:00 в часовом поясе профиля. Учитываются подходы, тоннаж и группы мышц, сохранённые в снимках новых записей; для старых записей группы мышц не угадываются.
- API фиксирует ID тренировки или ключ недели перед отправкой, чтобы повторный state push или tick не создал дубликат. Это best-effort, at-most-once: при сбое отправки автоматической повторной попытки нет. Живой Bot API для нового поведения не проверялся. `node scripts/dev.mjs` очищает токен, использует отдельный `.cache` профиль и не вызывает Bot API.
- Offset увеличивается после успешного ответа либо намеренного игнорирования update; подтверждается последующим `getUpdates`. Обновления в пакете сортируются, дубликаты пропускаются. Сетевые ошибки, 429 и 5xx повторяются с задержкой; при 429 учитывается `retry_after` (до 3600 секунд). Другие ошибки останавливают процесс, не теряя текущий update намеренным подтверждением.
- Доставка **не exactly once**: если Telegram принял сообщение, но ответ потерялся, повтор может создать вторую кнопку. Offset хранится в памяти; при перезапуске Telegram может повторно доставить еще не подтвержденный update. Постоянный checkpoint не реализован. Старые накопленные команды Telegram также могут быть обработаны — это по-прежнему ответы на команды, не рассылка.
- SIGINT/SIGTERM прерывают запрос и ожидание повтора; процесс завершается нормально. При остановке посреди отправки текущий update может остаться неподтвержденным.
- В логах только фиксированные диагностические сообщения; исходные HTTP-ошибки, Telegram description, токен, тела ответов и URL запросов не печатаются. Не включайте внешнее HTTP debug-логирование с токеном в URL.

## Проверка без Telegram

```text
node --test integration/telegram-bot.test.mjs
```

Тесты подменяют `fetch`, не загружают реальные секреты и не обращаются к Telegram. Проверяют конфигурацию, allowlist, приватность команд, webhook-конфликт, offset и дубликаты, повтор после сетевой ошибки, 429, скрытие секретов и остановку long poll. Импорт модуля сам по себе не запускает бот.
